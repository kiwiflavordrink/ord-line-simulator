# ORDR 메모리 진단 (읽기 전용)

오버레이가 게임 중 보유 패를 자동으로 읽게 하려고, 워크3 메모리에서 유닛 정보가 어디에 어떤 모양으로 있는지 찾는 첫 단계다(수정내역 42).

- 게임 프로세스를 **읽기 권한만으로** 연다(`PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`). 게임 메모리에 쓰거나 주입하지 않는다.
- 주의: 읽기 전용이라도 다른 프로그램이 게임 메모리를 읽는 것은 블리자드 약관상 회색지대다. 사용 여부는 사용자가 판단한다.

## 실행

1. 이 폴더의 `memscan.bat`과 `memscan.ps1`을 **같은 폴더**에 받는다.
2. 원랜디 게임 중(유닛을 가진 상태)에 `memscan.bat`을 더블클릭한다. 가진 유닛 코드와 개수를 입력하면 1차 스캔, 게임에서 그중 하나의 개수를 바꾸고 바뀐 개수를 입력하면 2차 스캔을 한다. 두 스캔의 차이로 실제 유닛 객체를 찾는다.
3. 바탕화면의 `ordr_memscan_1.json`, `ordr_memscan_2.json`을 보낸다(개수 메모가 파일에 들어 있다). `OpenProcess failed`가 나오면 bat을 우클릭 → 관리자 권한으로 실행.

PowerShell에서 직접: `powershell -ExecutionPolicy Bypass -File memscan.ps1 -Codes h006,h001,h008`

결과 파일에는 코드가 나온 주소와 그 앞뒤 96바이트만 들어간다. 계정·채팅 같은 정보는 찾지 않는다.

## 보유 패 읽기 (hand.bat)

두 번 스캔으로 찾은 구조(2026-10-21, 워크3 3.0.1.24371): 유닛 기록은 유닛 코드 바로 뒤에 색 이름 문자열(`|cff20b2aa나미|r - |cff00ff00흔함|r`)이 붙어 있다. 코드 앞 24바이트의 정수가 주인 플레이어 번호다(0 = 플레이어 1, 7 = 선택창에 표시되는 유닛, 5·6 = 적, 27 = 중립). 사라진 유닛은 앞 48바이트 값이 0x11이고 앞 88바이트의 두 정수가 −1이다. 다른 슬롯이면 `-Player 1`(플레이어 2) 식으로 준다. `hand.bat`은 코드 입력 없이 이런 기록을 모두 찾아 보유로 보이는 것을 세어 보여 주고, 바탕화면 `ordr_hand.json`에 원자료를 남긴다.

아직 확인할 것: 잠긴 유닛(시작 특별함 크로커다일)은 이 기록이 없다. 내 유닛 중 앞 88바이트의 두 번째 정수가 100000을 넘는 기록은 보유 개수와 맞지 않은 적이 있어 "확인 필요"로 따로 보여 준다.
