# 스턴 평가 (희귀 이상, 수정내역 32)

사용자 요청: "스턴 능력도 좀 평가를 해 보자. 유닛별로 스턴의 조건을 두고 평가해 봐. 희귀급 이상으로만."

## 방법

- 대상: `dist/data.json`에서 흔함·안흔함·특별함을 뺀 모든 유닛 중 스턴이 있는 137종과 엔진 보조(레일리·시키 전설·퀸).
- 스턴마다 발동 조건(공격당 확률·마나·체력·주기·보스/광폭 전용), 범위/단일, 일반 지속과 보스·광폭 지속(저항 스킨)을 데이터 그대로 적었다.
- **라인 지수** = Σ 초당 발동 × 일반 지속(발동 하나당 3초 상한) × 범위 가중. 범위 가중은 반경/550이고, 단일 스턴은 0.25다(550 범위 스턴의 1/4). 보스·광폭 전용 스턴은 뺀다.
- **보스·광폭 지수** = Σ 초당 발동 × 보스 지속. 라인 전용 스턴은 뺀다.
- 두 지수 모두 바르톨로메오 전설 = 1로 나눴다(라인 1.65초/초, 보스 0.54초/초).
- 사용자 기준과 비교: 쿠마 폭군 전설은 **0.48**("쿠마 0.5")이다. 드래곤 전설은 **0.78**("드래곤 1")로, 공속(5.13 대 5.56)과 범위(500 대 550) 차이만큼 낮다.
- 재계산: `node scripts/stun_index.mjs 0.25 docs/results/32_stun_index.json`

## 한계

- 이 지수는 데이터만으로 계산한 값이다. 위치 모델에 "딜 없이 스턴만" 넣어 본 시뮬 검증(`controlOnly` 옵션)에서는 스턴만 넣어도 남은 몹이 늘어나는 경우가 나왔다. 예를 들어 루치 전설은 21~23기가 20~28기가 됐다. 위치 모델은 모든 유닛을 생성 지점 한 곳에 두므로, 스턴이 막 나온 체력 많은 몹을 붙잡는 동안 깎인 몹이 사거리를 벗어난다. 실제 클리어 재현율이 45%에 그친 것과 같은 원인으로 보고, 위치 모델 배치를 고칠 때까지 시뮬 기반 스턴 점수는 쓰지 않는다.
- 같은 버프를 쓰는 스턴끼리 겹치는 문제, 스턴끼리의 중첩, 넉백·속박은 따로 보지 않았다.
- 그린블러드(2.305: 3초마다 825범위, 40만 + 최대체력 0.4% 고정, 1.2초 스턴, 보스 0.24초)는 같은 식으로 계산하면 라인 0.36, 보스 0.15다. 아직 엔진 옵션은 아니다.
