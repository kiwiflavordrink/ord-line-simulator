# 스택 시나리오 (zero / half / max)

`stacks.json`의 변형을 `dist/data.json` 메모리 복사본에 적용하고 `simulateV2`(신, 기본 옵션)를 1기·3기로 돌렸다. 결과 칸은 `1기 / 3기`, 각각 `판정 ·남은 몹 수(remaining)`. NaN·예외 0건.

- 변형 형식: `variants.<level> = {events: {<이벤트 index>: 덮어쓸 필드 | {removed: true}}, auras?, forms?, team_effects?, attack_uptime?}`. 바뀌는 필드만 넣었다.
- `data_level`: 지금 data.json 값이 어느 수준인지. `max`면 max 변형은 `{}`이며 생성식으로 데이터와 같은지 검사했다. `zero`/`other`면 max 변형에 실제 값을 넣었다. 엔진 `stackVariant`는 `max`일 때 저장된 데이터를 그대로 쓰므로, 이 영웅들은 데이터를 max로 바꾸거나 엔진이 max 변형을 적용하도록 해야 max가 계산된다.
- 엔진 교차 확인: 기본 스택에 `hero.stack.variants`를 넣고 `options.stackLevels`로 돌린 결과가 직접 적용과 같았다. 예외는 TR24로, `attack_uptime`을 엔진 `stackVariant`가 덮어쓰지 않아 3기 피해가 0.001% 다르다.
