# ORDR.kr 전체 유닛 정보와 시뮬레이터 검증

## 수집 범위

- 출처: [ORDR.kr 캐릭터 도감](https://ordr.kr/character), 수집 시각은 `dist/ordr_units.json`의 `retrieved_at_utc` 참조.
- 271종의 코드·이름·등급·역할·원문 URL·조합 명령·재료·추가 재료·상위 조합을 등록했다.
- 상세 스킬 또는 버프·디버프 설명은 200종에 있다. 15종은 스킬 본문 없이 버프·디버프 설명만 있다. 특성강화 스킬 변형은 27종이다.
- 각 유닛에 원본 페이지와 추출된 툴팁의 SHA-256이 있다. 원본 HTML은 `.cache/ordr`에 내려받되 Git에는 올리지 않는다.
- `dist/units.html`에서 전체 도감을 검색하고 원문과 연결할 수 있다. `dist/ordr_units.json`은 Claude Code와 다른 프로그램이 읽는 데이터 원본이다.

## 데이터와 계산의 경계

| 파일 | 의미 |
| --- | --- |
| `dist/ordr_units.json` | 현재 홈페이지에 표시된 유닛 정보의 텍스트 스냅샷 |
| `dist/data.json` | 일부 영웅과 몹의 계산 입력. 과거 맵 값과 수기 근사가 포함됨 |
| `dist/engine.mjs`, `dist/engine_v3.mjs` | 실제 시뮬레이션 구현 |
| `dist/units.html` | 스냅샷 열람 화면. 계산 구현 여부를 별도 표시 |

전체 도감 등록이 전체 271종의 피해 계산 완료를 뜻하지 않는다. `has_tooltip=false`인 71종은 홈페이지에 상세 스킬·버프 설명이 없으며, 재료·상위 조합 정보는 있을 수 있다. 평타, 확률, 범위, 타깃팅, 스턴, 변신 시간과 버프 중첩은 툴팁만으로 확정하지 못하는 경우가 있다.

## Claude Code 검증 순서

1. `python scripts/validate_ordr_tooltips.py`로 271종, 상세 200종, 특성강화 27종과 소스 일치를 확인한다.
2. `dist/v3.html`에서 선택할 수 있는 유닛 코드를 목록화한다. `dist/data.json`의 31종, `SUPPORTS`, `CONDITIONAL_UNITS`, `DELETERS`를 합치되 중복 코드는 한 번만 센다.
3. 유닛마다 `base_lines`와 `trait_lines`를 **각각** 원문과 맞춘다. 버프·디버프 전용 유닛은 `base_info.buff_lines`를 본다. 변신 전·후의 스킬을 중복 합산하지 않는다.
4. 각 피해 효과를 `발동 조건 / 확률 또는 절대쿨 / 대상 / 범위 / 피해 타입 / 고정값 / 현·잃·최대 체력 비율 / 자원 소모 / 특성강화 / 변신`으로 분해한다.
5. 이 효과가 계산 코드의 어느 함수·필드로 들어가는지 적고, 없는 효과는 `미구현`으로 표시한다. 근거가 불명확하면 `미검증`으로 표시한다.
6. 방깎·마방깎·증폭 같은 디버프는 적용 순서와 중첩 규칙을 맵 또는 패치 노트에서 따로 검증한다. ORDR의 수치만으로 엔진 공식을 확정하지 않는다.
7. 사례를 한두 개 골라 특정 효과를 켜고 끈 계산 차이를 확인한다. 기존 테스트 `node test_v2.mjs`, `node test_single.mjs`, `node test_conditional.mjs`도 돌린다.

Claude Code에 줄 요청 예시:

> `CLAUDE.md`와 `docs/ORDR_툴팁_검증_계획.md`를 읽고, `dist/ordr_units.json`의 모든 유닛 중 현재 v3에서 선택 가능한 유닛부터 툴팁 대 계산 코드를 대조해 줘. 각 스킬의 근거 문장, 구현 위치, 검증 테스트, 미구현·불확실한 항목을 표로 작성해. 우선순위가 높은 누락을 실제 코드와 테스트에 반영하되, 툴팁만으로 알 수 없는 수치는 추정이라고 표시해. 원본 맵과 추출 파일은 수정하지 마.`
